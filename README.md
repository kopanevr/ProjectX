# Eye Retail Project

**Проект объединяет технологии искусственного интеллекта, компьютерного зрения и решения для розничной торговли среднего формата.**

**Технологическим ориентиром при создании концепции послужила экосистема [Amazon Go](https://www.aboutamazon.com/news/company-news/amazon-fresh-go-stores-closing-expanding-whole-foods).**

Retail-focused computer vision MVP project.

Inspired by [Amazon Go](https://www.aboutamazon.com/news/company-news/amazon-fresh-go-stores-closing-expanding-whole-foods) project.

## Цель (Goal)

**Простая аналитика для среднего бизнеса. Менеджмент следит за метриками в реальном времени, получает прогнозы и важные уведомления. Система собирает регулярные дайджесты и понятно предоставляет простые ответы на любые вопросы по показателям.**

**Пример уведомления:** `«Внимание! За последние 2 часа трафик на входе вырос в 2 раза.»` `«Внимание! Конверсия выросла на 2.0 % по сравнению с понедельником. Это связано с ... Рекомендую ...»`

**Пример для ответа на вопрос пользователя:**

**Пользователь:** `«Почему во вторник упала выручка?»`

**Ответ системы:** `«Во вторник с 15:00 до 18:00 лил сильный дождь. Трафик упал на 40%. При этом средний чек вырос на 500 рублей, что частично компенсировало спад.»`

**Пользователь:** `«Что скажешь о данных за прошедший год по сравнению с текущим?»`

**Ответ системы:** `«В текущем году удалось значительно увеличить конверсию. Принятые решения позволили ...»`

**Пример дайджеста:** `«Итоги недели: Конверсия составила 15.5%. +1.5% к прошлой неделе. Самый эффективный день — четверг. Акция на ... сработала отлично! Рекомендую ...»`

Вышепредставленные примеры показывают всего лишь направление мысли, а не итог работы системы.

The goal is to optimize the interaction between management and analytics for medium businesses, enabling real-time data tracking of key metrics and predictions based on received metric data.

## Задачи

Одной из задач данного проекта является разработка работающего прототипа устройства (MVP) для проверки ключевых гипотез, в связи с чем строгое следование стандартам проектирования на данном этапе не предусмотрено.

## Описание (Description)

### Описание системы

Архитектурно система состоит из удаленного сервера и устройства для подсчета посетителей. Последнее фиксирует количество вошедших посетителей, получает данные от касс заведений о закрытых чеках, агрегирует эти сведения и отправляет их на сервер.
Подключение устройства к кассам и сети Интернет осуществляется по проводному интерфейсу с использованием протокола `HTTPS`. Располагается устройство у входа в заведение и предназначено для подсчета вошедших и вышедших посетителей.

**В общем архитектуру системы можно представить как:**

**Архитектура:** `«Камера с ИИ-чипом + Web-сервер на борту + Llama.cpp на сервере + Telegram-бот»`

### Описание устройства

Устройство представляет собой компактный вычислитель с камерой, предназначенный для подсчета посетителей, сбора данных с касс заведений, их агрегации, обработки и последующей отправки на удаленный сервер. Устройство имеет один порт PoE Ethernet (RJ45).

## Техническое описание

Для обнаружения объектов применяется предобученная модель [YOLO26s](https://huggingface.co/Ultralytics/YOLO26).

Устройство с периодичностью 5 минут в формате JSON производит отправку агрегированных данных на удаленный сервер.

**Формат данных передаваемых на удаленный сервер:**

```json
{
    "meta": {
        "version": 1,
        "subversion": 0
    },
    "device_id": 0,
    "interval_start": "2026-10-21T09:00:00Z",
    "interval_end": "2026-10-21T09:05:00Z",
    "data": {
        "visitors_in": 1,
        "visitors_out": 1,
        "receipts_count": 0,
        "total_revenue": 5000.0
    },
    "diagnostic": {
        "device_state": "OK"
    }
}
```

**Ключевые параметры:**

* **interval_start:** Дата и время начала периода агрегации данных (ISO 8601).
* **interval_end:** Дата и время окончания периода агрегации данных (ISO 8601).
* **data:** Блок с метриками за указанный интервал.
* **diagnostic:** Информация о текущем состоянии устройства.

После успешного закрытия чека на кассе данные в формате JSON автоматически передаются на устройство. Устройство производит запись полученных данных в конец во временный лог-файл с расширением `.log`.

**Формат данных записываемых при закрытии чека:**

```json
{"timestamp": "2026-10-21T09::00.00Z", "receipt_id": 0, "total_revenue": 0.0}
```
**Ключевые параметры:**

* **receipt_id:** Идентификатор чека (ID).
* **total_revenue:** Общая выручка.

Для проверки работоспособности сервера и корректности записи чеков выполните POST-запрос с помощью утилиты curl.

**Шаблон запроса:**

```bash
curl -X POST "http://X.X.X.X:X/receipts" \
    -H "Content-type: application/json" \
    -d '{"receipt_id": "X", "total_revenue": X}'
```

С периодом в 1 минуту счетчик клиентов производит запись полученных данных во временный лог-файл, также имеющий расширение `.log`.

**Формат данных записываемых счетчиком клиентов:**

```json
{"timestamp": "2026-10-22T09:16:39.00.00Z", "visitors_in": 0, "visitors_out": 0}
```

**Ключевые параметры:**

* **visitors_in:** Количество клиентов вошедших в заведение.
* **visitors_out:** Количество клиентов вышедших из заведения.

> [!WARNING]
> Все `.log` файлы записываются во временный каталог Linux `/tmp`.

Для проверки работоспособности и корректности отправки данных на удаленный сервер возможно использовать [test.py](scripts/test.py).
